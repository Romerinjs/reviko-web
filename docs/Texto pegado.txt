Quiero que diseñes y construyas una landing page completa, moderna, premium y altamente cuidada para una marca llamada “reviko”.

IMPORTANTE:
No quiero una landing genérica de SaaS creada con patrones típicos de IA.
La web debe sentirse como una extensión natural de la identidad visual de reviko y de sus publicaciones de Instagram.

Antes de implementar:
1. Inspecciona el proyecto/repositorio existente.
2. Identifica framework, arquitectura, dependencias, sistema de estilos y componentes ya disponibles.
3. Adáptate al stack actual.
4. No reemplaces arquitectura funcional existente sin necesidad.
5. Si el proyecto está vacío, usa:
   - React
   - TypeScript
   - Vite
   - Tailwind CSS
   - Motion / Framer Motion para animaciones
6. Construye componentes reutilizables y mantenibles.
7. No hagas una simple maqueta: quiero una landing terminada y responsive.

==================================================
1. SOBRE REVIKO
==================================================

reviko es una plataforma de fidelización para negocios físicos.

Permite que negocios como:

- restaurantes
- cafeterías
- barberías
- centros de uñas / estética
- autolavados
- comercios locales

puedan premiar las visitas de sus clientes y aumentar la recurrencia.

La propuesta no debe comunicarse como software corporativo.

La idea principal es mucho más sencilla:

“Haz que vuelvan.”

Otros conceptos de marca:

- Premia cada visita.
- Convierte clientes ocasionales en clientes de siempre.
- Cada visita cuenta.
- Más visitas. Más ventas. Clientes más felices.
- Clientes de hoy. Más visitas mañana.
- Fidelización simple para negocios reales.

reviko debe sentirse:

- simple
- moderno
- cercano
- elegante
- joven
- premium pero accesible
- comercial
- amigable
- tecnológico sin verse frío
- optimista

18. MOTION SYSTEM
==================================================

Quiero que la landing tenga bastante vida.

Pero movimiento ≠ exceso.

Las animaciones deben mejorar:

- jerarquía
- narrativa
- percepción premium
- storytelling

Utilizar Motion / Framer Motion cuando tenga sentido.

Crear primitives reutilizables como:

<Reveal />
<Stagger />
<SplitTextReveal />
<ParallaxMedia />
<Counter />
<RewardProgress />

No es obligatorio usar exactamente esos nombres, pero sí abstraer animaciones repetidas.

==================================================
19. ON SCROLL / REVEAL
==================================================

Implementar:

1. Fade-up:
opacity 0 → 1
y: 30 → 0

2. Stagger:
cards / steps / stamps

3. Text line reveal:
cada línea entra desde abajo dentro de un overflow hidden.

4. Image reveal:
clip-path o mask.

5. Parallax:
muy leve.
No más de aproximadamente 5-10% de desplazamiento.

6. Scale reveal:
0.96 → 1

7. Counters:
contar cuando entren al viewport.

8. Progress animations:
stamps/rewards completándose.

9. Sticky storytelling:
solo en desktop y únicamente donde agregue valor.

10. Scroll progress:
opcionalmente utilizarlo en determinadas secciones.

==================================================
21. REGLA DE PERFORMANCE
==================================================

Las animaciones deben mantener 60fps.

Priorizar:

transform
opacity
clip-path cuando sea razonable

Evitar animar:

height
width
top
left

cuando pueda resolverse con transform.

No instalar GSAP si Motion es suficiente.

No añadir librerías pesadas innecesariamente.

Lazy-load de imágenes no críticas.

Optimizar imágenes.

Evitar listeners manuales de scroll cuando IntersectionObserver / Motion pueda resolverlo.
